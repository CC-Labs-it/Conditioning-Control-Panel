Grace and entitlement (#4073)

Most of the conflict list, and the part that changes money. All five rules hold on this head:

  • The tier is kept on a launch where a reading can land (ProviderSubscription.InitializeAsync; an id with no token still zeroes it).
  • Grace renews on any reading with a tier (RenewGrace, through EntitlementReadings).
  • The same lower reading at least 90 s later closes the grace, with no session, engine, Lockdown or game running (AccountSeed.HoldGraceClose). A heartbeat comes every 120 s, so a close lands about two minutes after the first lower reading.
  • EntitlementLapse.Enforce only clears flags. Nothing restores a setting. A close repaints through AccountSeed.GraceClosed, not TierChanged, so it does not celebrate.
  • A closed plan answers "subscribe" rather than "reconnect" (TierGate.ReconnectIsTheAnswer in Core, so both heads).

WPF keeps EntitlementTierSync as main has it. EntitlementReadings is the settings half for a head without it. Draft #3301 adds a rise-only EntitlementTierMonitor; re-cut it onto ApplyTierReading, because a rise-only path on a kept tier never renews a grace.

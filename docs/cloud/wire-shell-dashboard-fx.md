# wire-shell-dashboard-fx

- Ported the browser frame and loading status portion of WPF `MainWindow.DashboardFx.cs:823-919` into the existing dashboard funnel. The frame travels for 2.4 seconds, holds until the discrete reset at 2.45 seconds, and rests until the 14-second cycle repeats. The loading badge uses WPF's 0.35–1 sine pulse with a 1.6-second half-cycle.
- The existing browser status text is watched directly, with localized, trimmed, case-insensitive loading recognition. Connected and failed messages immediately restore opacity to 1. Motion Reduced/Off, Performance mode, inactive/minimized windows stop these clocks; hidden tabs park through the existing shared 30 fps `BeatLoop`; closing the shell releases both loops. No animation runs on a Transform and nothing paints over or moves the native browser surface.
- Added `DashboardBrowserFxTests.BrowserFrameSweepsAndLoadingPulsesWithMotionGate`: stepped-time sweep positions, discrete reset and next cycle, status changes, Reduced/Off/Performance/minimize, hidden tab parking, rearming, and close cleanup. Uses the test assembly's sandbox profile.
- Only ledger row `shell-dashboard-fx` changed; it stays **stub**. Follow-up **wire-shell-dashboard-fx-b** must implement the mystery tile's unopened-date badge, synchronized glow/badge breath, hover reveal with proportional interruption-safe flip and tab-hide cancellation, plus custom still-logo drift and occasional sheen. Those interactions, their XAML and full regression coverage exceed this brief's combined line budget. The retired premium quick-toggle rail effects are not requirements of the current WPF: the favorites rail replaced that rail.
- Read-only trunk inspected at `a4ee52d40cd347d288dcf7fdaa8445b79f8e5038`; no files imported from trunk. Existing head files won; implementation adapts the WPF reference directly. No new panic surface is created: these are decorative loops belonging to the existing shell.

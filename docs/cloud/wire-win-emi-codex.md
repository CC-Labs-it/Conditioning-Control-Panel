## Remaining work: wire-win-emi-codex-b

The Avalonia desk service has no `Fire` moment bus and no two-chip ask/effect surface. Core `EmiLineEngine` intentionally refuses asks when the head's situation/effect probes are unset. The existing WPF `codex` door and '?' chip open the flipbook, not this reader, so pointing those controls here would invent the wrong route.

1. Wire the desk moment/ask bus and real `bookOffer` caller after tour finish/skip, with the existing engine's once-ever budget, ask cadence, feasibility, a re-armable 20-second delay, and live eligibility recheck.
2. Wire `book:open` to the existing flipbook via `EmiDeskWindow.OpenBook`, matching WPF `EmiOffers.RunBook` -> `EmiBook.Open`. Preserve bookmark/open counting and the normal flipbook door; the current WPF offer does not call `EmiCodex.Open`.
3. Port the currently unreachable `EmiCodex.Open` service/host and existing `Assets/web/codex` page only with its WPF lifecycle; do not invent a UI caller. Use the shared web host and local-origin lockdown. Implement ready/open/target/tour/close messages, bookmark boot delivery, catalogue/tier validation and strict named-tour parsing. Keep a plain-reader fallback for missing bundle/runtime, navigation failure and process failure. The shared `WebHost` currently exposes navigation completion without success status and no process-failure event, so those failure seams need an adapted implementation rather than claiming fallback proof from a URL alone.
4. Prove that user path with headless tests and rendered PNGs; test platform adapters on their actual OS where required. Register any newly introduced surface if WPF panic closes it. This slice adds no surface and changes no visual layout.

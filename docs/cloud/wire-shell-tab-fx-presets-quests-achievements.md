# wire-shell-tab-fx-presets-quests-achievements

- Ported the coherent focal-FX slice from WPF `MainWindow.TabFxPresetsQuestsAchievements.cs`: selected preset/session card sheen follows the actual selected card, detaches on rebuild/selection/hide/unload/window close, and follows active-window, minimized, motion, performance and mod gates. It reuses `CardSheenAdorner` and its shared clock; no new loop, timer, overlay or panic surface was introduced.
- Preset chips use the WPF 1.02 hover scale, session rows lift -2 without scaling, and the two primary buttons squish to 0.97 for 80 ms. Existing row sweeps remain owned by the view. Finite arrival stagger uses independent zones, 40 ms slots capped at six, 220 ms opacity and 260 ms translation. Transform transitions avoid `Animation.RunAsync` on a Transform.
- Weekly quest progress uses the existing Core service fraction and a 0.6 s QuadraticEaseOut width transition. A resize seats the current fraction immediately; motion Off seats interaction/progress endpoints. No business logic was duplicated or moved into the head.
- Read-only import source inspected: `parity/trunk` at `a4ee52d40cd347d288dcf7fdaa8445b79f8e5038`. No trunk files were imported; existing BASE builders and controls were retained. BASE: `goongame-core-c` at `0e1aa0473e7a5b6120544923e94bb04cc62a7e50`.
- The ledger row remains **stub**. Follow-up lane **`wire-shell-tab-fx-presets-quests-achievements-b`** must finish the WPF arrival funnel: discover/synchronize custom sessions from disk before building the rack; refresh and order the recent-session rack; populate/refresh the real Takeaway receipt shelf before its entrance animation (the BASE shelf is still a separate stub); and guard the outgoing tab's transient visibility changes using the shell's incoming-tab intent. This slice animates the existing live preset/session builders and does not invent receipt data. Achievements FX were already ported and remain untouched.

# wire-shell-notifications-toasts

- Ported WPF `ShowSticky`/`Dismiss(key)`: pre-host replay, duplicate-key suppression, indefinite display, programmatic dismissal, action dismissal without suppression, and user dismissal remembered in settings across reloads. Key validation/dismissal rules live in Core `NotificationDismissals`; WPF delegates to the same rules.
- Existing catalogue/deeper approval paths now call `ShowSticky` with WPF's stable catalogue-ID keys instead of a 15-second timeout. The catalogue acceptance test proves the notice remains after 16 seconds and that × remembers the key.
- Ported WPF's secondary-action row, wrapping buttons, action exception containment, primary/secondary colours, 13-pixel message text and 20-pixel line height. Pending notices retain both callbacks.
- Fixed fade removal to remove a toast from its original host when another host attaches during the fade. The old behavior left the original toast in its panel.
- Pink Rush now reuses `AchievementPopup.PlacePassive` before showing: scaled bottom-right placement and the existing X11/Win32 no-activate shim. Existing `pink-rush` PanicSurfaces registration is retained and its tests pass.
- The two touched notification/catalogue test fixtures use the shipped app builder for bundled font registration; existing assertions were retained and catalogue lifetime/dismissal assertions were added.
- Source: WPF reference on `origin/avalonia-port/goongame-core-c`, plus the existing WPF catalogue/deeper accepted-notice callers. `parity/trunk` was fetched/read at `a4ee52d40`; no code imported from that branch.

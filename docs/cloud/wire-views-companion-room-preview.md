# Companion room preview: chat and memory exhibits

- The preview state strip now seats fresh, detached chat and diary viewmodels, rather than changing only its label. It covers the WPF `default`, `freeTier`, `dormant`, `empty`, `drained` and `disabled` combinations for these two zones. The diary stays readable on the free tier; the dormant opener has no AI badge; fresh accounts have an empty thread and the three Level 1 profile stats.
- Unknown keys preserve the current models and label. Re-selecting a valid key resets the exhibit. Disabled-chat navigation is assigned on every switch, and a pending diary wipe confirmation is disarmed before replacing its model.
- The WPF harness deliberately has no normal-app caller. Avalonia keeps its existing `Launch()` driver entry point and clickable state strip; no startup hook was invented. No new panic surface: WPF does not close this harness on panic, and this slice adds no media or model work.
- Kept `views-companion-room-preview` as `stub`. Follow-up **`wire-views-companion-room-preview-b`** must compose the six remaining isolated mocks (hero, personality, awareness, attention, engine and workshop), restore the full room viewmodel accessor and navigator fan-out, and ensure all eight zones remain mock-only after visibility refresh. `drained` cannot yet change attention. Full composition requires adapting the WPF zone contracts and mock families beyond this bounded slice. The other six zones still read live state and their existing commands are not yet a safe mock artboard.
- Read-only `parity/trunk` inspected at `a4ee52d40cd347d288dcf7fdaa8445b79f8e5038`; its preview remains the same label-only stub. No trunk code was imported. Behaviour was adapted from the WPF preview window, `MockCompanionRoomVm`, `MockChatThresholdVm` and `MockMemoryDiaryVm`, reusing the Avalonia zone viewmodels.

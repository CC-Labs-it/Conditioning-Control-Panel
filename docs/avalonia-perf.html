Avalonia performance parity

Numbers come from --perf-bench <out.json> (CCP.Avalonia/PerfBench.cs), run on the real windowing platform, never headless. Decision and threshold: docs/avalonia-decisions.html (2026-10-23). A row passes when the Avalonia median is ≤ WPF median × 1.10 + 20 ms (memory: ≤ WPF × 1.10), both heads measured back to back on the same windows-latest runner. Linux is information only. A row with no WPF number is a gap, not a pass.

What is measured

  • Startup: a Stopwatch started on the first line of Main, stopped when the render thread has drawn the first frame after the shell's Opened. The shell is built straight after SetupWithoutStarting: no splash, no account/session seeding, no launcher routing. startup_since_process_ms adds the runtime's own start-up (process start time to the same frame).
  • Tab switch: ShowTab (the call every rail handler makes) to the next rendered frame, for every panel in NavCheck.TabPanels, 21 cycles with the first discarded; median (middle pair averaged) and p95 (nearest rank) per tab.
  • Memory: working set after the cycles and two GC.Collect + WaitForPendingFinalizers passes.
  • Exit 0 with the JSON written; 3 when a tab is missing or does not show; 4 on a frame timeout (30 s).

JSON shape ccp-perf-bench/1 (the WPF twin writes the same shape, head: "wpf"):

{ "schema": "ccp-perf-bench/1", "head": "avalonia", "os": "...", "runtime": "...",
  "startup_ms": 0, "startup_since_process_ms": 0, "working_set_mb": 0, "cycles": 20,
  "tabs": [ { "tab": "SettingsTab", "median_ms": 0, "p95_ms": 0 } ] }

CI: job perf-bench-linux in .github/workflows/build.yml (xvfb, report-only, artifact perf-bench-linux).

Startup deferral and review reconciliation

The final lane tree matches 74ac6ce3d5e0ae082c2871c00e864943e15aa2ad outside seven startup files. WPF, Core, all ten language files, Rain assets/web modules and original tests are restored byte-for-byte. This replaces the earlier inherited-diff exemption: the final full diff must be under 600 changed lines. History is retained by one corrective fast-forward commit.

  • ExclusivesTabView defers its hidden shelf, spotlight and backdrop until navigation, following WPF MainWindow.Exclusives.cs:EnsureExclusivesBuilt. Studio defers hidden rack art; its module controls, settings subscriptions and safety locks remain eager. Hidden mod/language/ entitlement changes are applied on the next visit.
  • Normal desktop startup defers Discord presence, dependency diagnostics and updater work until render acknowledgement. AfterFirstFrame races that acknowledgement against surface hide/close and shell closure; a disappearing launcher/game selects a replacement or the no-frame tray fallback. Work runs once, and shell closure cancels pending startup. WPF initializes presence and its updater independently of rendering; loss of a launcher must not suppress either service permanently.
  • Program logging, phrase custody, localization/fonts, settings/secrets migration, session/lockdown/ remote recovery, age gates and panic setup retain their order. LibVLC and duck-journal recovery remain before normal shell input; the web server remains lazy. StartupLadder's passive queue is unchanged.

The Avalonia benchmark builds the shell directly and does not run normal desktop service startup; it measures the hidden-art changes, not the service deferrals. Earlier Linux measurements were on abe6c1925 and its startup patch, not this reconciled tree: three paired startup medians 7903.6 → 6939.2 ms, final-binary sample 7766.9 ms. Contended exploratory full-tab runs were slower (7696.4 → 8473.4 ms; memory 890.9 → 1319.5 MB; Exclusives median 768.71 → 1271.37 ms). These are historical observations, not a performance result for this revision or proof of Windows parity.

AfterFirstFrameTests exercises real window events/dispatcher hops with controlled render acknowledgements: render ordering, once-only tray restore, shell-close cancellation and launcher close/hide with replacement or no-frame fallback. PerfBenchTests also verifies hidden art stays unloaded through shell Loaded and loads on navigation. The lifecycle fail-proof disables the surface close/hide subscriptions temporarily; all four recovery cases must fail with TimeoutException before restoring and rebuilding the fixed source.

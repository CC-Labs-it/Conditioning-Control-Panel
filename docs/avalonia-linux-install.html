Linux install experience (user request, 2026-09-28) — DO NOT DROP

Goal: installing CCP on Linux must be easy for a non-technical user. Installing CCP installs every dependency; the user never has to find packages by hand. This belongs to the installer / Linux package phase (phase 5) and must be done before "retire WPF from shipping" counts as finished.

Why this came up

On a fresh box, web features show "WebKitGtk library is not installed. Install webkit2gtk 4.0+ package." The user had to install webkit2gtk-4.1 by hand. Avalonia.Controls.WebView 12.1.0 loads the GTK3 builds only (libwebkit2gtk-4.0.so.37 or libwebkit2gtk-4.1.so.0 + libjavascriptcoregtk-4.1 + libsoup-3.0/2.4); webkitgtk-6.0 (GTK4) does NOT work.

Updates come from the store. Host: own Flatpak repo + .flatpakref on the website first; Flathub only after checking its content policy for this app.
  2. AUR package (Arch/CachyOS): depends=(webkit2gtk-4.1 gst-plugins-good vlc libpulse libsecret libx11 libxi icu), the WPE trio in optdepends (opt-in engine since 2026-10-13). Debian/Ubuntu/Fedora: no WPE packages exist, which no longer matters: web pages run on WebKitGTK there too, and the in-app messages (startup toast, WebHost panel) no longer name WPE (LinuxDependencies.Required/WebViews).
  3. Later, on demand: .deb / .rpm with the same dependency lists; AppImage only as a fallback (cannot pull WebKit).

Installing the tarball by hand

The tarball's .desktop runs conditioning-control-panel from PATH, so extracting it alone gives a menu entry that does not start. Lay it out the way the AUR package does (any prefix; ~/.local needs no root). The last line points the menu entry at the launcher's absolute path, since ~/.local/bin is often not on the desktop session's PATH:

mkdir -p ~/.local/opt ~/.local/bin
tar -xzf ConditioningControlPanel-<ver>-linux-x64.tar.gz -C ~/.local/opt
mv ~/.local/opt/ConditioningControlPanel ~/.local/opt/conditioning-control-panel
printf '#!/bin/sh\nexec %s "$@"\n' ~/.local/opt/conditioning-control-panel/CCP.Avalonia > ~/.local/bin/conditioning-control-panel
chmod 755 ~/.local/bin/conditioning-control-panel
cp -r ~/.local/opt/conditioning-control-panel/share/. ~/.local/share/
sed -i "s|^Exec=.*|Exec=$HOME/.local/bin/conditioning-control-panel|" ~/.local/share/applications/io.github.CodeBambi.ConditioningControlPanel.desktop

Remove: delete opt/conditioning-control-panel, bin/conditioning-control-panel and the io.github.CodeBambi.ConditioningControlPanel.* files under share/applications, share/icons/hicolor/*/apps, share/metainfo.
